# منصة بشمهندس إسماعيل أحد — أساس التطبيق

تطبيق عربي باتجاه RTL، بخادم Express وMongoDB/Mongoose. يعرض الطالب كورسات صفه فقط، ويشترط التسجيل اختيار الصف. يتحقق الخادم من الجلسة والاشتراك قبل إرجاع الدروس والملفات والامتحانات. لا توجد بيانات تجريبية مزروعة تلقائيًا.

تعرض لوحة الطالب مخطط أيام المذاكرة للأسبوع الحالي من الأحد إلى السبت، ويرتفع العمود بحسب وقت المشاهدة المحفوظ في كل يوم. يبدأ المخطط أسبوعًا جديدًا تلقائيًا عند حلول الأحد.

تعرض لوحة الطالب ترتيبه بين الطلاب النشطين في صفه فقط، من دون إظهار أسماء أو درجات الآخرين. يُحتسب الترتيب من متوسط تقدم الدروس ودرجات أفضل محاولات الامتحانات المنشورة في الكورسات المشترك بها.

تُحفظ مرفقات PDF والفيديوهات التي تُرفع من لوحة الإدارة داخل MongoDB GridFS، وتبقى محمية بفحص اشتراك الطالب مع دعم طلبات Range للفيديو. الحد الافتراضي لحجم الفيديو 1 GB ويمكن ضبطه عبر `MAX_VIDEO_UPLOAD_MB`. روابط الفيديو الخارجية تبقى مدعومة، لكنها لا تُنسخ إلى قاعدة البيانات؛ لتخزين الفيديو نفسه ارفعه كملف من لوحة الإدارة. الملفات المرفوعة قبل هذا التغيير تبقى في مسار التخزين المحلي السابق، ويمكن فتحها، أما الفيديوهات القديمة ذات الروابط الخارجية فتظل خارج قاعدة البيانات.

## المتطلبات

- Node.js 20 أو أحدث وnpm.
- MongoDB يعمل محليًا أو قاعدة MongoDB مستضافة.
- حساب Kashier ومفاتيح API لتفعيل الدفع الإلكتروني (اختياري؛ يبقى الشراء المدفوع مغلقًا دونها).

## التشغيل على Windows PowerShell

```powershell
Copy-Item .env.example .env
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

ضع القيمة المولّدة في `JWT_SECRET` داخل `.env`، واضبط `MONGODB_URI`. إذا ظهر `querySrv ECONNREFUSED` مع عنوان `mongodb+srv://` لأن الراوتر يحجب استعلامات MongoDB SRV، أضف `MONGODB_DNS_SERVERS=1.1.1.1,8.8.8.8` إلى `.env` ليستخدم التطبيق هذه المحلّلات فقط دون تغيير إعداد DNS في Windows. يضبط التطبيق هذا الخيار قبل الاتصال بقاعدة البيانات؛ ويتطلب السماح باستعلام DNS إلى هذه العناوين عبر الشبكة. لا تضف ملف `.env` إلى Git ولا تشارك مفاتيح الإنتاج. ثم:

```powershell
npm install
npm test
npm start
```

افتح `http://localhost:3000`. نقطة `/api/health` تعيد حالة عدم الجاهزية إذا لم يتصل الخادم بقاعدة البيانات.

إذا ظهر `bad auth` أو `authentication failed` بعد حل DNS، فتحقق من أن `MONGODB_URI` يستخدم اسم مستخدم قاعدة البيانات وكلمة مروره من MongoDB Atlas (وليس بيانات تسجيل دخول حساب Atlas)، وأن المستخدم لديه صلاحية على قاعدة البيانات المطلوبة. عند تغيير كلمة المرور، حدّث الرابط في `.env` مع ترميز محارف URI الخاصة مثل `$ : / ? # [ ] @` بصيغة percent-encoding.

لإنشاء المدير الأول، عيّن كلمة مرور قوية مؤقتًا في جلسة PowerShell ثم نفّذ الأمر مرة واحدة:

```powershell
$env:ADMIN_EMAIL = "admin@example.com"
$env:ADMIN_PASSWORD = "replace-with-a-unique-password-of-14-chars"
npm run bootstrap:admin
Remove-Item Env:ADMIN_EMAIL
Remove-Item Env:ADMIN_PASSWORD
```

أداة التهيئة لا تعيد تعيين مدير موجود، وكلمات المرور تُجزّأ باستخدام bcrypt قبل تخزينها. أضف صفًا دراسيًا من لوحة المدير أولًا، ثم أنشئ الكورسات والدروس.

## Kashier

إعداد الدفع اختياري. يظل الدفع المدفوع مغلقًا ما لم تُضبط القيم الثلاثة التالية في `.env`:

- `KASHIER_MERCHANT_ID`
- `KASHIER_API_KEY` (Payment API Key)
- `KASHIER_SECRET_KEY`

يستخدم `KASHIER_MODE=test` بيئة الاختبار افتراضيًا. يجب أن يكون `WEB_ORIGIN` عنوان HTTPS عامًا؛ لا تقبل Kashier `localhost` كعنوان عودة صالح. عند التطوير المحلي، استخدم نفقًا عامًا مثل Cloudflare Tunnel أو ngrok، وضع عنوان HTTPS الذي يوفره النفق في `WEB_ORIGIN` في ملف `.env`، ثم أعد تشغيل الخادم. عيّن عنوان إشعارات الدفع في Kashier على `https://<نطاقك>/api/payments/webhook`، واسمح بحدث `pay`. بعد إتمام اختبار الدفع، اضبط `KASHIER_MODE=live` واستخدم بيانات live من لوحة Kashier. الخادم ينشئ جلسة الدفع ويعيد توجيه الطالب إلى صفحة Kashier المستضافة. لا تُمنح صلاحية الكورس من رابط العودة أو المتصفح؛ لا يتم تفعيلها إلا بعد التحقق من توقيع `x-kashier-signature` ومطابقة مرجع الطلب والمبلغ والعملة وحالة النجاح في إشعار الخادم. يجب أن يكون عنوان Webhook متاحًا للعامة عبر HTTPS حتى تستطيع Kashier الوصول إليه.

احتفظ بمفاتيح Kashier في `.env` على الخادم فقط، ولا تشاركها أو تضعها في الواجهة الأمامية أو المستودع. تفاصيل الجلسات والتوقيعات موثقة في [وثائق Kashier الرسمية](https://developers.kashier.io/docs/accept-payments/payment-sessions) و[دليل Webhooks](https://developers.kashier.io/docs/webhooks).

بيانات الفوترة المطلوبة تُؤخذ من ملف الطالب؛ لا يرسل التطبيق رقم هاتف تجريبيًا. يلزم إكمال رقم الهاتف في الملف قبل بدء الدفع. عند فشل اتصال البوابة، يُعلّم الطلب بالفشل ولا تُمنح صلاحية.

## أهم مسارات API

- `POST /api/auth/register|login|logout` و`GET /api/auth/me|profile`
- `GET /api/grades`, `GET /api/courses`, `GET /api/courses/:id`
- `POST /api/checkout/:courseId`, `GET /api/dashboard`
- `GET /api/courses/:id/content`, `GET /api/lessons/:id`, `GET /api/files/:lessonId/:resourceId`
- `GET /api/videos/:lessonId` لبث فيديو الدرس المحمي من MongoDB GridFS
- `POST /api/exams/:id/start`, `POST /api/exams/:id/attempts`, `GET /api/results`
- `/api/admin/*` لإدارة الصفوف والكورسات والدروس وملفاتها والامتحانات والإعلانات والطلاب والمنح اليدوية
- `POST /api/admin/lessons/:id/resources` و`POST /api/admin/lessons/:id/video` لرفع PDF والفيديو إلى GridFS
- `POST /api/payments/webhook` لتأكيد إشعار Kashier الموقّع

تُنشأ الامتحانات من لوحة الإدارة عبر نموذج مرئي للأسئلة والاختيارات والإجابة الصحيحة، مع دعم الاختيار من متعدد والصح والخطأ، دون إدخال JSON يدويًا.
إعادة فتح امتحان لم يُسلَّم تستكمل الجلسة نفسها ومؤقتها، ولا تُستهلك المحاولة عند رفض إجابات غير صالحة.

كل تغيير عبر المتصفح يمر بفحص CSRF مزدوج، وملف جلسة HTTP-only وSameSite Strict. مسارات الإدارة تتحقق من دور المدير على الخادم. ملفات PDF الخاصة تُحفظ خارج `public`، ولا يُسمح بعرضها داخل المتصفح إلا بعد فحص الاشتراك.

روابط الفيديو المباشرة للدروس تُشغّل داخل مشغل المنصة بصيغ MP4/WebM، ويدعم HLS ملفات `.m3u8` عبر hls.js محلي. استضافة الفيديو الخارجية يجب أن تسمح بطلبات CORS والنطاقات (Range) للموقع؛ لا يرفع التطبيق ملفات الفيديو إلى الخادم، لذا قد يتمكن من يحصل على الرابط الخارجي من مشاركته. لحماية أقوى استخدم مزود فيديو خاصًا بروابط موقعة قصيرة العمر. يُحفظ موضع المشاهدة تلقائيًا للمستخدم الذي يملك صلاحية الكورس، ويُستأنف عند فتح الدرس مجددًا.

## ملاحظات قبل الإنتاج

- الخادم لا يقدم `private-uploads` كملفات عامة. استخدم تخزينًا خاصًا أو خدمة CDN بروابط موقعة للفيديو والملفات الكبيرة. رابط الفيديو HTTPS يُكشف فقط بعد فحص اشتراك الطالب، لكن منع إعادة مشاركة رابط مضيف خارجي يتطلب رابطًا قصير العمر وموقّعًا من مزود الفيديو.
- إعدادات العودة إلى الموقع وWebhook يجب ضبطها في لوحة بوابة الدفع؛ لا تعتبر صفحة النجاح تأكيدًا.
- أضف نسخًا احتياطية ومراقبة وتنبيهات ومراجعة تشغيلية لمفاتيح الدفع، وسياسة احتفاظ بالبيانات وخيارات استعادة الحساب قبل الإطلاق العام.
- الإعلانات الموجهة تظهر للمستخدم المؤهل وتُحفظ علامة إغلاقها في متصفحه لمنع تكرار النافذة في كل تنقل. يمكن للإدارة إيقافها.
